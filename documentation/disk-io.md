# Disk IO

Solarr shares each disk between the work that wants it, and leaves an idle disk alone.

**Layout.** `internal/platform/disktopo` reads `/proc/self/mountinfo` and `/sys` and places each root folder (and the config folder) in a *disk group*: a ZFS pool (`zfs:tank`), a network server (`net:nas`), a physical disk (`disk:sda`, partitions and device-mapper volumes resolved to it) or, failing all that, its filesystem (`fs:<device>`). Filesystems nothing else could place are joined when they report the same size and free space. Settings -> Disk (expert, administrator) shows the result and why, and a group name typed there replaces the detected one (setting `disk.group_overrides`).

**Gate.** `internal/platform/iogate` gives each group slots (2; 4 for the shared `*` group; fewer while the disk answers slowly). The classes, most urgent first: playback, import, rename, tag write-back, drain, scan, probe, statistics, recycle bin, previews. The last six classes can never take the final slot, so urgent work always finds room; a waiter moves up one class per 30 seconds it waits, so nothing starves. Two ways to take a turn. A *whole-run* job (scan and rescan by their `root_folder_id`; statistics, recycle bin and preview cleanup in the shared `*` group) holds one slot from the executor for its run. Every other listed job takes turns *per batch*: the code that touches a disk wraps it in `iogate.OnDisk(ctx, kind, paths, fn)`, which takes a slot on every disk group under those paths (in group order, so two batches needing the same pair cannot deadlock) and gives them back when `fn` returns. Wrapped today: probe (ffprobe batches, oshash, perceptual hash), tag write-back (each page of edits), move/rename/drain (`mover.ApplyOne` and keep-source copies; a rename counts as rename, anything else as drain), link-identical (each link), and every import placement (`mover.PlaceOneOnDisk`: movie, TV, book, adult, music). `fn` must not nest another `OnDisk`. Outside a job (an API call, a test) `OnDisk` just runs `fn`.

**Latency.** `internal/platform/disklatency` times a directory read per group. It runs only while a job waits for a group (rate limited to once per 5 s per group) or when an administrator presses Measure now. The scheduled capacity and reachability checks skip a root whose group was unused for 30 minutes and which already has a reading.

**Child processes.** ffprobe, fpcalc and the other background tools run under `ionice -c2 -n7`; the playback conversion under `-c2 -n0`. Without the `ionice` tool they run unchanged.

**Watching.** `internal/platform/fswatch` is inotify (standard library). `internal/scanning/watch` chooses what to watch from the library's own records (no disk is read): the root, then each deeper level in turn, and where the budget runs out inside a level the directories that received files most recently first. The budget is half of `/proc/sys/fs/inotify/max_user_watches`. A change in a watched directory is rescanned as that directory alone (`library.rescan`) once it has been quiet for 20 s, or after 3 min of continuous changes; a new directory is watched at once. The choice is redone every 30 minutes. The Disk page shows the limit, the budget, the watches held, and the limit the host would need for every directory to fit: the next power of two of the directory count, doubled.

**When a root is scanned** (`watch.ScanDue`, the scheduled scan still fires every 6 hours and each root is asked): at start only if its last scan finished over 12 hours ago; "Run now" always; the person's own interval (Disk page) when set; otherwise weekly if a watcher has been alive since the last scan without losing events and covers the artist/series/movie level; daily while the root's used space and top-level entry count equal what they were at the last scan; every 6 hours when nothing cheap can be learned. A watcher is not believed on a network share or FUSE mount, where files change without the kernel here hearing of it. Lost events (queue overflow) or a watch registered after the last scan also end the belief until the next scan.

Not built yet: playback does not take a gate slot (its conversion has the ionice priority only); import inspection (reading the download folder) and sidecar extras are not gated. Watching at depth 1 sees a new artist or series folder but not a file added to an existing season folder; that waits for the weekly scan unless the budget reaches the deeper levels (it does on any host with a normal inotify limit).
